## New depth method

**EG360**, [original November12 preprint](https://arxiv.org/abs/2611.16793v1), [original full text](https://arxiv.org/html/2611.16793v1), predicts full-ERP metric radial depth by reciprocating a metric inverse-depth head. Geometry-adaptive distillation combines DAP and MoGe2 teachers; SCFF fuses spherical features. The perspective teacher is not a student pinhole interface, and cubemap teacher views do not imply a stereo baseline or raw-fisheye support.

Author timing is6.593M parameters,23.492GFLOPs and28.509ms/35.08FPS on Jetson Orin NX16GB MAXN with PyTorch eager,AMP FP16,batch1 and structural reparameterization. It averages300 forward passes after warm-up, excluding I/O/CPU preprocessing and using model-native resolutions. Table3 has no ground-truth alignment; **DAP has lower AbsRel on all three datasets** (0.137/0.072/0.195 versus EG3600.173/0.094/0.237). This is an efficiency/accuracy tradeoff, not demonstrated DAP accuracy superiority. Official student code and weights are not verified; the abstract promises future code.

## New VO/SLAM records

- **S²D-FVO**, [November9 v1](https://arxiv.org/abs/2611.11934v1), [full text](https://arxiv.org/html/2611.11934v1): main raw-fisheye path remaps to ERP, while **separate SectionV-A, TablesXIV-XV explicitly evaluate ERP and pinhole depth/VO**. Thus all three classes are paper-supported; the ERP label is not inferred from internal remapping. Spherical-log-map residuals and median radial-depth regularization couple depth learning and tracking. DepthNet starts from UniDAC pseudo depth. Global Sim(3) loop correction is present. Trajectories use global Sim(3) alignment; TableVII depth comparisons use median alignment. Learned scale consistency does not establish unaligned metric inference. No verified complete official implementation/checkpoint or new NIO/Blender/derived-split download found.
- **CoSphere-SLAM**, [November17 v1](https://arxiv.org/abs/2611.22235v1), [official project](https://cosphere-slam.github.io/): multi-agent monocular ERP Gaussian mapping, SO(3) loop matching, global Sim(3) consensus and per-keyframe scale correction. External ERP input is explicit. Six co-centered cube faces are internal projections; the multi-camera attribute refers to independent agent cameras. Metric3D supplies early priors but absolute global monocular scale remains unobserved. The paper reserves inertial/ranging metric constraints for future work. Per-agent tracking is1Hz; A100 global refinement is offline. Holo360D split into200 virtual-agent routes and360Loc cross-session tests are derived protocols, not newly released raw datasets or independent truth. The [project source tree](https://github.com/cosphere-slam/cosphere-slam.github.io) contains webpage/demo assets; the project promises future code and benchmark tools. No estimator or full weights release established.
- **DEFDVO**, [November14 v1](https://arxiv.org/abs/2611.19095v1), [official main](https://github.com/BurakSevsay/DEFDVO): direct ERP, sparse patch-based VO with spherical-prior deformable features and seam-aware estimation. Structure is **inverse Euclidean radial range**, replacing inverse Z. Training pose loss and trajectory scoring use Sim(3) alignment. Loop closure/global optimization are future work. The abstract claims code availability, but reviewed main `ebb70e4f793cc53dafcc60a07ae226da9b2dc64b` contains only README promising future release; no implementation or checkpoint verified. WACV2027 acceptance is author-reported, not already published proceedings. Author reports7.1FPS at1920x960/192patches on RTX A5000, not a local measurement.
- **sqrtVINS360 / Hilti2026 entry**, [November16 report](https://arxiv.org/abs/2611.20568v1), [full text](https://arxiv.org/html/2611.20568v1): two calibrated **raw fisheye streams plus IMU**, with EUCM projections, point/line square-root filtering, SALAD loop proposals and non-causal GTSAM refinement. Internal ERP descriptors do not establish a full-ERP input API. IMU and a genuine inter-camera baseline support metric local scale; tightly regularized calibration and one global scale variable do not remove origin/yaw gauges. No dense depth or LiDAR input. Final trajectory can be revised with future loop/BA observations. The exact full challenge workspace/weights/terms were not independently located; paper ROS2 descriptions and an existing sqrtVINS frontend are not a complete challenge release. This is a technical report rather than an ordinary new ICRA conference paper; ranking is not independently asserted.

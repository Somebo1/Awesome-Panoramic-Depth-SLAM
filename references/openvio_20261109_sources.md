## Verified addition: OpenVIO

- [Original arXivv1](https://arxiv.org/abs/2610.41671v1), submitted October30, and [full manuscript](https://arxiv.org/html/2610.41671v1). This was missed in the previous run and is now an overlap/backfill addition, not a paper first published in the November9 week. Sole listed author: Seungwon Choi. An institutional affiliation is not explicitly stated in the reviewed manuscript; it was not inferred from an email address.
- [Official repository](https://github.com/93won/openvio), reviewed at commit `997de9b8a66a372ab5b15506a1bde957592ad356` (November2 docs/paper citation). Actual estimator, initializer, tracking, odometry and camera source files are present, together with configs and optional ROS1/ROS2 nodes. This is not a README-only release. [MIT LICENSE](https://github.com/93won/openvio/blob/997de9b8a66a372ab5b15506a1bde957592ad356/LICENSE) was read; third-party dependency terms remain separate. No learned checkpoint is needed by the reviewed system.
- [Camera documentation](https://github.com/93won/openvio/blob/997de9b8a66a372ab5b15506a1bde957592ad356/doc/camera_models.md), [configuration rules](https://github.com/93won/openvio/blob/997de9b8a66a372ab5b15506a1bde957592ad356/doc/configuration.md), and actual [ERP camera source](https://github.com/93won/openvio/blob/997de9b8a66a372ab5b15506a1bde957592ad356/src/vio/sensor/equirectangular_camera_model.cc) distinguish three released direct input modes. Already two-lens-stitched fullERP plusIMU is **monocular**. Calibrated pinhole-radtan and equidistant-fisheye support either mono or synchronized physical-baseline stereo plusIMU. A stitched ERP frame is not a separate stereo mode. Thus the method can carry an overall multi-camera attribute because of the real stereo modes, without claiming ERPstereo.
- The estimator is a filter-based MSCKF design with persistent sparse landmarks. Inertial units and known gravity provide metric visual-inertial scale, while the local global-position/yaw reference remains arbitrary; optional stereo has a calibrated baseline. No external absolute pose reference is an input and no independent wrist-level accuracy was established.
- No dense depth product is output. The internal sparse inverse-depth parameterization rotates the anchor ray to local+Z; it must not be labeled a fullERP Z-depth or range map. Outputs include exposure-time **IMU** poses, filter states, sparse landmarks and keyframes/observations. [Usage](https://github.com/93won/openvio/blob/997de9b8a66a372ab5b15506a1bde957592ad356/doc/usage.md) exports IMU trajectory in eight-column TUM format.
- [Architecture](https://github.com/93won/openvio/blob/997de9b8a66a372ab5b15506a1bde957592ad356/doc/architecture.md) and the paper conclusion explicitly exclude loop closure/map reuse. Short-term landmark re-finding is not global loop closure; callbacks only allow an extension to be written.
- Camera–IMU timing/extrinsic corrections are estimated online. Two-lensERP adds a one-parameter angular stitching correction and back-lens exposure delay. [PanoAir config](https://github.com/93won/openvio/blob/997de9b8a66a372ab5b15506a1bde957592ad356/config/panoair.yaml) excludes polar tracking bands; these refinements are not arbitrary rig dewarping or universal camera self-calibration.
- PanoAir evaluation uses one run on each of17flights, omits the first12.5s and reports mean ATE1.14m after rigid alignment. There is no independent calibration reference; the stitching prior is based on earlier online estimates on the same dataset without groundtruth. This is not claimed as untuned zero-shot calibration. 30Hz is an input frequency, not a processing-throughput measurement. No local timing, peak memory or estimator run was performed.
- Standalone C++17/CMake/OpenCV/Eigen/libpng implementation and optional ROS Noetic/Humble/Jazzy support are documented. Build scripts may install system dependencies, so they were not executed during this source review. The October30 [v1.0.1 notes](https://github.com/93won/openvio/blob/997de9b8a66a372ab5b15506a1bde957592ad356/release_notes/v1.0.1.tex) cover ROS support; source/docs presence does not mean local compilation was tested.
